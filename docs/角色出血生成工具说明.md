# 角色出血生成工具说明

> 位置：`KfuPet-Tool\docs\rebleed.ps1`（辅助源码 `Rebleed.cs.txt`）
> 作用对象：KfuPet 的角色包（`KfuPet\Characters\<角色>\`）
> 性质：**开发期手动执行的脚本**，不参与 KfuPet 编译，不随软件发布

---

## 1. 它解决什么问题

角色部位图是刚性位图，关节处没有重叠时，一转动就会裂开。裂缝大小与「接缝半长 × sin θ」成正比。

这个脚本按角色原画重新裁切部位图，沿接缝方向多保留一圈**本来就该被邻居挡住**的像素（出血），再额外生成关节补片和 `attachments` 配置草案。

几何依据见主仓库文档：`KfuPet\docs\设计\无缝变形与自主控制方案.md` 的 4.2 / 4.3 / 附录 B。

---

## 2. 脚本做什么、不做什么

| 做 | 不做 |
|---|---|
| 读角色包里的原画（默认 `baiyy.png`） | 不修改现有 `images/` |
| 按事实表裁切 + 外扩出血边 | 不修改现有 `attachments.json` |
| 重算外扩后的 `pivot` | 不改 `offset` |
| 从切片内部生成 4 张补片 | 不重画被遮挡区域（原画里没有的内容做不出来） |
| 输出配置草案 `attachments_bleed.json` | 不自动替换、不自动提交 |

所有产物写入 `<角色包>\images_bleed\`，**必须人工目检后再手动替换**。

---

## 3. 前置条件

- Windows PowerShell 5.1（系统自带）
- 角色包内包含原画（默认 `baiyy.png`），且切片与它像素一致
- 角色包内已有 `character.json`（脚本用它判断目录是否是正确的角色包）

---

## 4. 快速开始

```powershell
powershell -ExecutionPolicy Bypass -File "H:\Visual Studio xiangm\KfuPet-Tool\docs\rebleed.ps1"
```

不传参数时：

- 角色包自动定位到 `..\..\KfuPet\Characters\白摇摇`
- 出血量取默认值（颈 16 / 肘 41 / 膝 44 px）

生成结果在 `KfuPet\Characters\白摇摇\images_bleed\`。

### 指定其他角色

```powershell
powershell -ExecutionPolicy Bypass -File rebleed.ps1 `
  -PackageDir "H:\Visual Studio xiangm\KfuPet\Characters\白摇摇-Beta" `
  -NeckBleed 20
```

## 5. 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-PackageDir` | 自动查找 | 角色包目录；找不到 `character.json` 会报错 |
| `-MasterFile` | `baiyy.png` | 原画文件名（位于角色包根目录） |
| `-OutSubDir` | `images_bleed` | 产物子目录名 |
| `-NeckBleed` | `16` | 颈部出血像素（`body.png` 顶边上扩） |
| `-ElbowBleed` | `41` | 肘部出血像素（小臂内侧端外扩） |
| `-KneeBleed` | `44` | 膝部出血像素（小腿上端上扩） |
| `-SkipPatches` | 关闭 | 只重切、不生成补片 |

出血量公式（换角色时按新 `scale` 重算）：

```text
建议出血(px) = 1.5 × (接缝像素长度 / 2) × sin(该关节设计最大角) / scale
```

## 6. 产物

```
<角色包>\images_bleed\
    body.png                 顶边外扩（颈）
    arm_left_lower.png       内侧端外扩（肘）
    arm_right_lower.png      内侧端外扩（肘）
    leg_left_lower.png       上端外扩（膝）
    leg_right_lower.png      上端外扩（膝）
    其余部位图               原样复制，便于整体替换
    patch_shoulder_l/r.png   肩部补片
    patch_hip_l/r.png        髋部补片
    attachments_bleed.json   配置草案（含新 pivot 与补片条目）
```

脚本会打印每条外扩边的**不透明像素数**，用于自检：某一行为 `0` 说明没裁到内容，参数或裁切矩形写错了。

---

## 7. 三条不能违反的规则

### 7.1 `offset` 不动，只改 `pivot`

外扩会让图片变大，`pivot` 是**比例**，必须重算；`offset` 是相对骨骼的偏移，外扩不改动它。

```text
新 pivotY = (旧 pivotY × 旧高 + 上方外扩像素) / 新高
新 pivotX = (旧 pivotX × 旧宽 + 左侧外扩像素) / 新宽
```

只改一个、不改另一个，图片一定会位移。

### 7.2 肩、髋不能靠重切解决

原画里肩被手臂压住、髋被裙子压住，**被遮挡的区域本来就没有画**。强行从原画裁会把邻居的像素裁进来，一转就露馅。所以这两处只生成补片：从对应切片内部切一角，保证 `alpha` 是原切片的子集，静止时被原图完全盖住。

### 7.3 小腿枢轴必须落在袜口

「白摇摇」的小腿图以袜口为可见接缝。把枢轴下移到解剖学膝盖会让袜筒绕新枢轴甩出约 17 DIP，反而在大腿处裂开。换角色时同理：**枢轴要放在美术的遮挡线/接缝上，不要放在解剖位置**。

## 8. 验收流程

1. 运行脚本，检查“出血校验”每项都大于 0；
2. 用开发者工具（`KfuPet-Tool`）连接，打开调试线框；
3. 依次设置：`head` ±18°、`arm_*_lower` ±60°、`leg_*_lower` ±40°、`arm_*_upper` 70°；
4. 目检接缝邻域不得出现画布背景色；
5. 确认无误后，把 `images_bleed\*.png` 覆盖到 `images\`，再把 `attachments_bleed.json` 改名覆盖 `attachments.json`。

IPC 命令格式（注意三层都是 PascalCase，`Params` 内是 camelCase）：

```json
{ "Service": "skeleton", "Action": "SetRotation", "Params": { "boneId": "head", "degrees": 15 } }
```

角度会被 `SkeletonService.RotationLimits` 收敛，超出限位会读回被夹住的值。

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `未找到角色包` | 用 `-PackageDir` 显式指定角色包目录 |
| 出血校验某行为 `0` | 外扩方向写反、裁切矩形不对，或原画与切片不匹配 |
| 覆盖后角色整体位移 | 只改了 `pivot` 或只改了 `offset`，回到 7.1 |
| 静止时补片露出轮廓 | 补片取了原切片以外的像素，重新按 7.2 的规则取角 |
| 转动后仍裂开 | 该关节属于「原画被遮挡」类型，只能靠补片；或枢轴不在接缝上（7.3） |

## 10. 修改事实表

脚本内两张表需要随美术资源变化更新：

- `$parts`：每张切片的裁切矩形 `X/Y/W/H`、`PivotX/PivotY`、外扩边 `Edge`、出血量 `Bleed`
- `$patches`：补片的取图来源 `SrcFile/SrcX/W/H`、`pivot`、`offset`、`zOrder`

裁切矩形可以用主仓库文档 4.2.1 的方法从原画反查得到。
